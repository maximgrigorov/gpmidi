# headlamp — AILab cluster dashboard

Lightweight Kubernetes web UI for this single-node k3s cluster: namespaces,
nodes, workloads, pods, status, events, logs, object YAML and related objects.

Installed from the official [kubernetes-sigs Headlamp Helm
chart](https://kubernetes-sigs.github.io/headlamp/), pinned in
[`../../versions.env`](../../versions.env).

## Why Headlamp

- The legacy **Kubernetes Dashboard** repository moved to `kubernetes-retired`
  and was archived on 2026-01-21.
- **Rancher** is built for multi-cluster fleet management. On one k3s node it
  would add a management stack far larger than the thing it manages.
- **Headlamp** is maintained under `kubernetes-sigs`, is a single small
  Deployment, and authenticates through ordinary Kubernetes RBAC.

## Resources

| File | Kind | Owner | Description |
|---|---|---|---|
| `namespace.yaml` | Namespace | repo | `headlamp`, PSS labels matching `gpmidi-ml` |
| `values.yaml` | Helm values | repo | Chart configuration (1 replica, explicit resources, no PVC/HA) |
| `rbac.yaml` | ServiceAccount + ClusterRoleBinding | repo | `headlamp-admin` login identity for the owner |
| `ingress.yaml` | Ingress | repo | `k8s.ailab.home.arpa` plus the hostless default route |
| Deployment, Service, ServiceAccount, ConfigMap | — | **Helm** | Created by the chart release |

The Ingress is deliberately *not* generated by the chart
(`ingress.enabled: false`): the routing model needs a hostless rule, and keeping
it here means one Ingress edit does not require a chart upgrade. Nothing is
declared in both places.

For the same reason `apps/headlamp` is **not** referenced from
[`../../kustomization.yaml`](../../kustomization.yaml). That root is a single
buildable reconciliation root; wiring in three of Headlamp's resources while Helm
owns the other four would make `kubectl apply -k` silently partial. The install
script is the entry point instead.

## Two ServiceAccounts, on purpose

| SA | Permissions | Used for |
|---|---|---|
| `headlamp` (chart) | **none** — no ClusterRoleBinding | The pod's own identity |
| `headlamp-admin` (repo) | `cluster-admin` | The token the owner pastes into the UI |

The chart's default is `clusterRoleBinding.create: true` with
`clusterRoleName: cluster-admin`, which would give the *pod* cluster-admin. That
is switched off. Headlamp forwards each browser session's bearer token to the API
server, so the pod SA is never the identity that reads cluster objects — and a
cluster-admin token mounted inside a network-facing pod would only ever be an
escalation path.

`config.unsafeUseServiceAccountToken` must stay `false`. Setting it true makes
Headlamp answer every visitor as its own ServiceAccount, i.e. an unauthenticated
dashboard. Nothing but Traefik sits in front of this UI — there is no auth proxy.

## Install / upgrade

Idempotent; re-running converges.

```bash
ssh mgrigorov@192.168.30.2
cd /path/to/gpmidi
bash infra/ailab/scripts/install-helm.sh        # once, pinned + checksum-verified
bash infra/ailab/scripts/install-headlamp.sh
```

## Log in

```bash
sudo k3s kubectl -n headlamp create token headlamp-admin --duration=24h
```

Minted on demand through the TokenRequest API, so it expires by itself and is
stored nowhere. Paste it into the Headlamp token prompt. Re-run when the session
expires. Never commit it.

## Access

| URL | Notes |
|---|---|
| `https://192.168.30.2/` | Default route, needs no DNS |
| `https://k8s.ailab.home.arpa/` | Needs the MikroTik A record |

Requires this static A record on the MikroTik:

```
k8s.ailab.home.arpa -> 192.168.30.2
```

The certificate is the shared self-signed `ailab-tls`, so browsers warn on first
visit. That is expected for this LAN-only PoC — see
[`../../scripts/ensure-ailab-tls.sh`](../../scripts/ensure-ailab-tls.sh).

## Verify

```bash
sudo k3s kubectl -n headlamp get deploy,pod,svc,ingress
curl -kfsS https://192.168.30.2/ | head -c 200          # Headlamp HTML
curl -k -o /dev/null -w '%{http_code}\n' https://192.168.30.2/api/v1/nodes   # 401 without a token
```

A `401` on the last command is the point: it proves authentication is enforced.

## Rollback

```bash
sudo k3s kubectl delete -f infra/ailab/apps/headlamp/ingress.yaml
sudo k3s kubectl delete -f infra/ailab/apps/headlamp/rbac.yaml
sudo env KUBECONFIG=/etc/rancher/k3s/k3s.yaml helm uninstall headlamp -n headlamp
sudo k3s kubectl delete namespace headlamp
```

Removing the Ingress hands the default `https://192.168.30.2/` route back to
nothing — Traefik will answer 404. The Phase 0 smoke-app used to own it; if that
behaviour is wanted back, restore the hostless rule in
`../../smoke-app/ingress.yaml`.
