# Задание: стоимость перемещения левой руки в микротайминге гитары

Статус: не начато. Ветка: `feat/fret-hand-cost`.

## Суть в одном абзаце

Проект **уже считает позицию левой руки** — `hand_position` как медиану ладов бита,
и хранит `previous_hand_position` (`gp_to_shreddage.py`, около строки 925). Дельта между
ними уже используется: при переносе на `min_fret_shift: 4` лада и больше с вероятностью
0.40 подмешивается скрип струны `fret_noise`. **Но на тайминг эта дельта не влияет.**
Пассаж с прыжком на семь ладов и пассаж на одной позиции получают одинаковый разброс,
хотя физически первый играть медленнее. Задание — связать уже посчитанную дельту
с микротаймингом.

## Почему это стоит делать

Владелец описывает результат как «техничный подросток, а не гитарист». Из механизмов,
отличающих живого от секвенсора, перемещение руки — единственный, который здесь
полностью отсутствует, при этом данные для него уже посчитаны, и он выводится из
механики инструмента, а не из вкуса.

Отдельная удача: `hand_position` считается **на бит**, а LESSONS.md §5 требует, чтобы
сдвиг был общим для бита. Модель ложится на существующую структуру без натяжек.

## Что УЖЕ сделано — не переделывать

| механизм | где | статус |
|---|---|---|
| позиция руки и её перенос | `gp_to_shreddage.py`, `hand_position` / `previous_hand_position` | считается, применяется к `fret_noise` |
| направление медиатора | `humanize.py: sixteenth_index()`, профиль: `alternate`, `upstroke_spread_k: 0.8`, `upstroke_vel: -4` | сделано. Версия «доля = вниз» отвергнута, давала три удара вверх подряд (LESSONS.md §7) |
| разброс штриха по аккорду | `pitched_strum_offsets()` | сделано |
| velocity по артикуляции | `pitched_velocity()`, потолок из `articulation_maps` | сделано |
| бенды, вибрато, слайды | `gp_to_shreddage.py` | стабильно, менять запрещено (AGENTS.md) |

**Арку фразы через velocity не делать.** У Hydra velocity — переключатель артикуляции:
120–126 = Rake, 127 = Pinch. Динамика к вершине фразы даст случайный визг. Если
понадобится — отдельное задание с выяснением, какой CC у Hydra отвечает за громкость,
по правилу LESSONS.md §8.

## Шаг 0. Проверить вход — ДО реализации

LESSONS.md §12: три задания подряд описывали реальность неверно. Это тоже может.

Снять по тестовым `.gp5` распределение `|hand_position - previous_hand_position|`
по гитарным дорожкам: сколько битов с нулевым переносом, сколько с 1–3, сколько
с 4 и больше. Отдельно — для быстрых мест (между атаками < 150 мс).

**Гейт:** если битов с переносом `>= 4` меньше 5% — остановиться и доложить.
Модель перемещения на материале без перемещений смысла не имеет. Замер положить
в `docs/evidence/`.

## Шаг 1. Модель

Задержка атаки бита как функция `|Δhand_position|`:

- `0` ладов — ноль задержки;
- растёт с расстоянием, с насыщением: рука не тормозит бесконечно;
- в пределах позиции (до 4 ладов, тот же порог `min_fret_shift`) — заметно дешевле,
  чем смена позиции.

Форма кривой и коэффициенты — в конфиг. В `.py` ни одного магического числа.

Смену струны в эту итерацию НЕ включать: `hand_position` построена только по ладам,
добавление струн требует менять способ её вычисления, а он уже используется
для `fret_noise`. Отдельное задание, если первое себя оправдает.

## Шаг 2. Конфиг

Новая секция в `config/humanize_profiles/guitar_metal.yaml`, `config_version` поднять.
Единицы — **только доли шестнадцатой (`*_frac16`)**: конвертер живёт на tpb=960,
standalone-скрипт на 480, абсолютные тики молча означают разное (LESSONS.md §7).
Порог переноса брать из `articulation_maps` (`min_fret_shift`), а не дублировать:
поменяется пресет — поменяется там.

Секция обязана нести комментарий в стиле файла: что меряли, какие числа вышли, почему.

## Шаг 3. Точка встраивания

1. **Сдвиг общий на бит.** Лиги и легато-перекрытие (`LEGATO_OVERLAP_MS=40`) считаются
   от `start_tick`; разъедутся ноты внутри бита — порвётся легато. `hand_position`
   уже побитная, так что это естественно.
2. **До эмиссии keyswitch.** KS приходит за `KS_LEAD_MS=15` до ноты; нота, уехавшая
   назад, окажется раньше своего KS и сработает чужая артикуляция.
3. **Только задержка.** Перемещение руки не может сдвинуть атаку вперёд.
4. **Не сломать `fret_noise`.** Он висит на той же дельте; после правки скрип обязан
   возникать на тех же битах, что и до неё.

## Шаг 4. Флаг и совместимость

Отдельный флаг, по умолчанию ВЫКЛЮЧЕН, как `--humanize` и `--ghost-notes`.
Без флага экспорт **байт-в-байт идентичен** замороженному baseline.

## Приёмка

Автоматическая, не на слух:

1. **`jitter_ms`** — сдвиг относительно ОБЪЕДИНЁННОЙ сетки (16-я + триоли), в мс.
   `pct_off_grid16` НЕ использовать: считает триоль живостью, на квантованном файле
   рапортует 54% (LESSONS.md §3).
2. **`RIGID`** из `verify_midi.py` — разброс внутри каждого питча.
3. **Профиль по LESSONS.md §6:** гитара timing std около 7 мс. Выход за 5–9 мс —
   объясниться, а не молча принять.
4. **Дифференциальная проверка, главная:** на битах с `|Δhand_position| >= 4` задержка
   статистически больше, чем на битах с нулевым переносом. Нет разницы — фича
   не работает, даже если общий `jitter_ms` вырос.
5. **`VEL_ZONE`, `KS_LEAD`, `PB_LEAK`, `BEND_CEILING`, `STUCK`** — без новых срабатываний.
6. **`fret_noise_events`** в статистике экспорта — не изменилось.

## Проверка самой проверки

LESSONS.md §11: «проверка, которая никогда не срабатывала, не проверена» — `CC1_PROPELLER`
дважды молчал на файле, ради которого написан.

Новую дифференциальную проверку прогнать на выходе с **выключенной** фичей и убедиться,
что она там ПАДАЕТ. Тест положить рядом.
