# Задание: интерфейс GP → MIDI как пошаговый мастер (по макету v2)

Статус: не начато. Ветка: `feat/ui-wizard`. Вливает агент-интегратор, не ты.

## Суть

Страница `templates/index.html` сейчас показывает всё сразу:
- до кнопки «Обработать» — 38 чекбоксов эффектов;
- пересобрать с другой опцией нельзя: `process_job` отвечает 409;
- скачивание разбросано по шапке и таблице.

Переделай её в мастер из пяти шагов — Файл → Дорожки → Звучание →
Дополнительно → Результат — по утверждённому макету. Каждая сборка становится
версией (v1, v2…), чтобы владелец сравнивал варианты на слух. **Музыка не
меняется:** та же отправка формы обязана давать те же байты MIDI.

## Инварианты (нарушение одного — PR не принимается)

1. **Конвертер не трогаешь.** `git diff --stat origin/main...feat/ui-wizard` не
   содержит:
   - модули конвертера: `gp_to_shreddage.py`, `humanize.py`,
     `articulation_config.py`, `verify_midi.py`, `*_check.py`,
     `playable_tabs.py`;
   - каталоги `config/`, `third_party/`, `services/`, `infra/`, `tools/`
     (кроме нового генератора фикстуры).

   Если без них не обойтись — остановись и спроси.
2. **Контракт формы прежний.**
   - Поля те же: `track_indices`, `track_<N>_<ключ>` со значением `on`,
     `seed`, `playable_tabs`, `prepare_arrangement_context`,
     `openai_arrangement_draft`, `arrangement_prompt`, `apply_token`.
   - `TRACK_EFFECTS`, `parse_track_options`, `default_track_effects` и
     `resolve_track_render_options` не меняются. `default_track_effects` —
     единственный источник дефолтов.
3. **Та же форма → те же MIDI.** Это проверяет эталонный тест этапа 0.
4. **Путь «ничего не трогать»** (файл → далее → далее → собрать) даёт нынешние
   дефолты: скрытые 32-е включены на всех тональных дорожках, авторские сдвиги
   GP8 — на соло, остальное выключено.
5. **Действующие опции.**
   - Зависимое поле с выключенным родителем получает `disabled` и не
     отправляется. Зависимости: от `humanize` той же дорожки — `ghost_notes`,
     `lock_to_drums`, `double_track`, `palm_mute_motion`, `fret_hand_cost`,
     `humanize_timing_over_gp_offsets`; от `preserve_gp_played_offsets` —
     `keep_gp_played_overlaps` и `humanize_timing_over_gp_offsets`.
   - Сервер повторяет эту проверку при записи версии в манифест: сводка не
     должна утверждать то, что конвертер проигнорировал. Сейчас её делает
     только JS.
6. **Старые сессии.** Манифест без версий открывается как одна версия
   «исходная сборка», все прежние ссылки на скачивание работают, файлы не
   переносятся.
7. **Стек.**
   - Flask + Jinja + ванильный JS, без сборки и новых зависимостей. Внешние
     ресурсы — только нынешние: soundfont-player с jsDelivr и Google Fonts.
   - Без JS форма работает: все секции видны подряд, таблица «по дорожкам»
     раскрыта.
   - Светлая тема, тексты по-русски. Технический ключ опции — в `title` и в
     подсказке по фокусу.
8. **Вёрстка.** 1440 и 375/390 px без горизонтальной прокрутки, цели нажатия от
   44 px, контраст текста от 4.5:1.
9. **Безопасность не ослабляется.**
   - Остаются: `Path(job_id).name == job_id`, привязка заданий к сессии, лимит
     загрузки, белый список файлов для скачивания и печати (`_artifact_names`).
   - Белый список ведётся по каждой версии отдельно.
   - Параметры `v` и `from` — целые в допустимом диапазоне, иначе 404.

## Порядок работы

Один этап — один или несколько коммитов, после каждого `pytest -q` и
`ruff check .` зелёные.

### Этап 0 — эталон (до любых правок интерфейса)

- **Фикстура.** `tools/make_wizard_fixture.py` строит через `pyguitarpro`
  небольшой `.gp5`:
  - дорожки: барабаны (percussion), бас, «Guitar (Solo)», «Guitar (Rhythm)» и
    одна прочая (например, «Keys»);
  - 8–16 тактов с hammer-on, бендом, palm mute, аккордом и паузой.

  Сгенерированный файл положи в `tests/fixtures/wizard_fixture.gp5`. Это наш
  синтетический файл, музыки владельца в репозитории быть не должно.
- **Тест `test_ui_form_golden.py`.**
  - Через тестовый клиент Flask: `POST /upload`, затем `POST
    /jobs/<id>/process` с формой.
  - Минимум пять наборов опций:
    1. только дефолты;
    2. оживление на всех ролях;
    3. оживление + `lock_to_drums` + `double_track` + `pick_direction` +
       `palm_mute_motion`;
    4. исключения по дорожкам: опция включена у одной дорожки роли;
    5. одна выбранная дорожка.
  - Собери все `.mid` (по дорожкам, «(double)», `_ALL.mid`) и сравни sha256 по
    имени файла с `tests/fixtures/wizard_golden.json`.
  - Файлы ищи через манифест или ссылки скачивания, а не по жёстким путям:
    на этапе 1 они переедут.
- **Запись эталона.** Отдельный скрипт с явным флагом, на `origin/main` до
  твоих правок. Закоммить JSON вместе с тестом.
- **Реальные файлы.** Если на машине есть
  `~/Documents/Music/1_Spring_Melody/Spring_Melody_v3_final.gp` и
  `~/cursor-eval/gpmidi/pnd.gp5`, сними такие же хэши и на них в локальный
  JSON, не коммить его. В конце сравни и приложи вывод в PR. GP8-фичи — скрытые
  32-е и авторские сдвиги — проверяются только на Spring Melody.

### Этап 1 — версии на сервере

- Каждый `POST /jobs/<id>/process` создаёт `renders/<n>/` и запись
  `job["renders"][n]`:
  - выбранные дорожки, опции и **действующие** опции, seed, флаги шага ④;
  - время, статус `ok` / `error` (+ текст ошибки);
  - список файлов, отчёт обработки.
- 409 снять. Разбор (`detected_tracks`) общий для всех версий.
- План выразительности и enriched-MIDI привязаны к версии, из которой собраны.
  `apply_token` — тоже на версию.
- Миграция при чтении: работа без `renders` читается как версия 1 из нынешних
  полей, файлы на месте.
- Маршруты:
  - `/jobs/<id>?step=tracks|sound|extra|result`;
  - `&v=N` — выбор версии на шаге результата;
  - `&from=N` на шаге звучания заполняет форму опциями версии N.
- Скачивание и ZIP — по версии; старые URL продолжают работать. Кнопка ZIP
  (маршрут `download_zip` уже есть) и `_ALL.mid` — на каждую версию.
- Тесты:
  - v2 не затирает файлы v1, хэши v1 после сборки v2 не меняются;
  - старый манифест открывается и скачивается;
  - неверные `v` и `from` дают 404;
  - `from=N` заполняет форму;
  - эталон этапа 0 зелёный.

### Этап 2 — шаги ①–④

- **Устройство страницы:** один шаблон сессии, частичные шаблоны на шаг, одна
  `<form>` на шаги ②–④. JS переключает секции, делает `history.pushState`,
  кнопка «назад» браузера возвращает шаг без потери значений.
- **Таблица «по дорожкам» — единственный источник полей.**
  - В ней все `input name="track_N_<ключ>"`, сервер рендерит их из
    `default_effects`.
  - Групповые контролы ролей — без `name`, с `data-role` и `data-effect`: ставят
    значение во все ячейки своей роли, где опция есть в `TRACK_EFFECTS`.
  - Ручная правка ячейки помечает её `data-exception`, групповой контрол такие
    ячейки не трогает. «Убрать исключения» выравнивает по группе.
- **Предупреждение** «вместе с барабанами без оживления барабанов» (или
  барабаны не выбраны) — с кнопкой «Оживить барабаны».
- **«Точность нот»** свёрнута, метка «по умолчанию / изменено · N», «Сбросить к
  умолчаниям».
- **Сводка «Что получится»** считается из ячеек таблицы, а не из групповых
  контролов.
- **Роль** — `select` только для GUITAR и BASS, начальное значение —
  `is_solo_track`, на сервер не уходит.
- **Телефон:** таблица превращается в аккордеон по дорожкам, как на
  `M3-Sound`.

### Этап 3 — шаг ⑤ и состояния

- **Результат — по `D5-Result` / `M5-Result`:**

  - главная кнопка «Скачать всё для Logic» (`_ALL.mid`) и ZIP;
  - карточки дорожек. Предпрослушка — нынешние `buildPreviewMarkup` /
    `wirePlayer` без изменений логики. Кнопки только для реально
    существующих файлов: MIDI, Double, «Табы ▾» (ASCII, PDF, печать A4 при
    настроенном принтере, GP с новой аппликатурой, параметры перегенерации);
  - «Что применено» по действующим опциям и строка «Отличие от v<N-1>»;
  - чек-лист «Настройка DAW» — только применимые пункты, отметки в
    `localStorage` на сессию;
  - «Изменить звучание и пересобрать» → `?step=sound&from=N`;
  - «Удалить сессию».
- **Состояния — по `S-*.dc.html`:**
  - пусто;
  - ошибка разбора;
  - слишком большой файл: проверка размера в браузере до отправки плюс

  - идёт сборка: сборка сейчас синхронная, поэтому индикатор показывается по

  - старая сессия;
