Спецификация для вёрстки

Flask + Jinja + ванильный JS. Один шаблон сессии, частичные шаблоны на шаг. Сервер получает ровно те же поля, что сейчас.

Устройство страницы

Шаг ①/ — зона загрузки. После успешного /upload — редирект на /jobs/<id>?step=tracks
Шаги ②–④Одна <form> в одном шаблоне, три секции. Сервер по ?step= ставит hidden лишним. JS переключает секции и делает history.pushState, popstate возвращает назад — значения формы не теряются
Шаг ⑤?step=result&v=N. Без v — последняя версия
Отправка«Собрать» — POST на /jobs/<id>/process, каждая отправка = новая версия (снять 409)
«Изменить и пересобрать»?step=sound&from=v2 — форма заполняется опциями v2 из манифеста
Без JSВсе три секции видны подряд, таблица «по дорожкам» раскрыта и работает — форма остаётся отправляемой

Как группы превращаются в поля

Источник правдыЧекбоксы таблицы «по дорожкам» — единственные input с name="track_N_ключ", value="on". Сервер рендерит их из default_effects
Групповые контролыБез name. data-role + data-effect: переключение ставит значение во все ячейки своей роли, где опция доступна
ИсключениеРучная правка ячейки → data-exception; групповой контрол такие ячейки не трогает. «Убрать исключения» выравнивает по группе
ЗависимостиЕсли родитель ячейки выключен, ячейка получает disabled и не отправляется — как в текущем UI. humanize → 6 опций; preserve_gp_played_offsets → перекрытия; оба → «поверх сдвигов»
РольТолько UI: data-role на строке дорожки, поля не шлёт. Смена роли переносит дорожку в другую группу; дефолты «Точности нот» не пересчитываются
ПредупреждениеЕсть дорожка с lock_to_drums и humanize, но ни у одной выбранной DRUMS нет humanize (или барабаны не выбраны)
