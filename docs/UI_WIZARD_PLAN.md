# План: веб-интерфейс GP → MIDI как пошаговый мастер (wizard)

Статус: план, 2026-09-26. Реализация — в отдельной сессии.
Предмет: страница `templates/index.html` и маршруты `/upload` → `/jobs/<id>` →
`/jobs/<id>/process` в `app.py`. Audio → MIDI (`sheetsage2.html`) и
Проекты (`projects*.html`) затрагиваются только навигацией (этап 4).

## 1. Цель и границы

**Цель.** Пользователь — гитарист. Он пишет партии в Guitar Pro и хочет их
«оживить» для Logic и Shreddage. Интерфейс должен вести его по порядку:
файл → дорожки → звучание → результат. Сейчас он показывает сразу все
переключатели на одном экране.

**Не меняется:**
- Музыкальная семантика. Одна и та же отправка формы даёт байт-в-байт те же
  MIDI, что и сейчас (AGENTS.md, «Definition of done for UI tasks»).
- Имена полей формы (`track_indices`, `track_N_<effect>`, `seed`,
  `playable_tabs`, `prepare_arrangement_context`, `openai_arrangement_draft`,
  `arrangement_prompt`) и разбор через `parse_track_options`.
- Дефолты (решение пользователя 2026-09-24): скрытые 32-е GP включены на всех
  тональных дорожках, авторские сдвиги атак — только на соло
  (`default_track_effects`), всё остальное выключено.
- Стек: Flask + Jinja + ванильный JS, без сборки и SPA-фреймворка. Светлая тема
  (AGENTS.md, правило 6).

## 2. Что сейчас (снято на `677eadb`, Spring Melody, 9 дорожек, окно 1440×900)

Поток разорван на две колонки:
- **Боковая панель:** шаг 1 (загрузка) и список сессий. Там же дублируется
  подсказка про PITCH BEND RANGE.
- **Основная область:**
  - шапка с плашками режимов (до 16 штук) и кнопками скачивания;
  - 6 карточек метаданных;
  - «Шаг 2»: карточка на каждую дорожку плюс блок «Обработка выбранных дорожек»;
  - после обработки — таблица результатов.

Инвентаризация:

| Элемент | Факт |
|---|---|
| Переключатели на гитарной дорожке | 12 чекбоксов в одной сетке (`TRACK_EFFECTS["GUITAR"]`), на басе 7, на барабанах 2 |
| На песню Spring Melody | 9 карточек, 38 чекбоксов эффектов (2 + 7 + 5×1 + 12 + 12) плюс 9 выбора дорожек до кнопки «Обработать» |
| Язык подписей | Смесь: «humanize velocity/timing», «keep GP played overlaps (Hydra legato)», «Подготовить expression context» |
| Зависимости | Текстом в подписи: «(needs humanize)», плюс JS-блокировка. В конвертере такие флаги без humanize просто игнорируются (`humanize_timing`, `hprof`) |
| Скрытая зависимость | «lock to drums» при выключенном оживлении барабанов привязывает к неоживлённой сетке: смысла нет, UI об этом молчит |
| Шаги | «Шаг 1» в боковой панели, «Шаг 2» в основной области, у результата номера шага нет, индикатора прогресса нет |
| Возврат | Нельзя. После обработки `process_job` отвечает 409 (`stage != "parsed"`); чтобы сменить опцию, файл нужно загрузить заново. Для сравнения на слух (A/B) это главная боль |
| Скачивание | Общий `_ALL.mid` вверху справа, по дорожке — в 6-й колонке таблицы, Double, табы и PDF — там же. Маршрут `/download/<id>/all.zip` есть, кнопки нет |
| «Enriched ещё не собран» | Показывается всегда, даже если expression не заказывали |
| Таблица результатов | 7 колонок, горизонтальная прокрутка уже на 1440 px. Форма перегенерации аппликатуры вложена в ячейку «Трек» |
| Телефон 375 px | Боковая панель идёт первой: содержимое сессии начинается с 1004 px |
| Навигация | `/projects` не связан с главной страницей (попасть можно только по URL) |
| Подсказка PB RANGE = 7 | Показана дважды. Остальные ручные настройки пресета не показаны нигде: Picking Mode 108/109 при `pick_direction`, Vel → Tightness при `palm_mute_motion` |

## 3. Целевой поток

Один экран — один вопрос. Шаг хранится в URL (`/jobs/<id>?step=…`) и рендерится
на сервере, поэтому «назад» в браузере работает. Сверху — степпер:

```
① Файл  ─  ② Дорожки  ─  ③ Звучание  ─  ④ Дополнительно  ─  ⑤ Результат
```

### ① Файл
- Большая зона перетаскивания во всю ширину. Сразу после разбора — переход на ②.
- Список сессий уходит в выдвижную панель или отдельную страницу «История».
  Боковая панель больше не несёт шагов.
- Метаданные песни (название, темп, такты, размер) — одна строка под заголовком
  вместо 6 карточек.

### ② Дорожки
- Компактный список: чекбокс, имя, распознанный тип (плашка) и **роль**:
  Соло / Ритм / Бас / Барабаны / Прочее. Роль выводится тем же кодом, что сейчас
  (`resolve_track_type`, `is_solo_track`), и только показывается: это не новая
  логика.
- «Выбрать все / снять все» и подсказка «можно оставить одну дорожку».
- Никаких эффектов на этом шаге.

### ③ Звучание — главный шаг
Опции сгруппированы по музыкальному смыслу, а не списком флагов на дорожку:

1. **Оживление** — главный выключатель и Seed. Выключено — «как в нотах»,
   экспорт как раньше.
2. **Барабаны**: оживление, гост-ноты.
3. **Ритм-секция** — ритм-гитары и бас:
   - вместе с барабанами (`lock_to_drums`);
   - второй дубль L/R (`double_track`);
   - глушение как движение руки (`palm_mute_motion`);
   - направление медиатора (`pick_direction`).
4. **Соло**:
   - задержка при переносе руки (`fret_hand_cost`);
   - вибрато на длинных нотах (`auto_sustain_vibrato`);
   - fret-noise (`fret_noise_on_hand_shift`);
   - направление медиатора.
5. **Точность нот** — свёрнуто, «для тех, кто знает»:
   - скрытые 32-е (`expand_gp_hidden_32nds`);
   - авторские сдвиги GP8 (`preserve_gp_played_offsets`);
   - перекрытия от сдвигов (`keep_gp_played_overlaps`);
   - оживление поверх авторского тайминга (`humanize_timing_over_gp_offsets`).

   Дефолты помечены «по умолчанию», есть кнопка сброса.

Правила отображения:
- Зависимости выражены **вложенностью**: всё, что требует humanize, лежит
  внутри включённой группы «Оживление», а не висит серым с «(needs humanize)».
- Групповая опция применяется ко всем дорожкам своей роли. Исключения задаются в
  раскрывающейся **матрице «по дорожкам»**: строки — выбранные дорожки,
  столбцы — опции, доступные для их типа (`TRACK_EFFECTS`). Матрица шлёт те же
  поля `track_N_<effect>`.
- Предупреждение: включено «вместе с барабанами», а оживление барабанов
  выключено.
- Подписи — по-русски, по-музыкальному. Технический ключ — во всплывающей
  подсказке (tooltip).

### ④ Дополнительно (можно пропустить)
Ортогональные конвейеры, у каждого своя карточка:
- Играбельные табы и GP с новой аппликатурой (`playable_tabs`).
- План выразительности (expression context / OpenAI). Эту карточку видно, только
  если `openai_configured`. Промпт свёрнут.

### ⑤ Результат
- Главная кнопка: **«Скачать всё для Logic (`_ALL.mid`)»**, рядом ZIP (маршрут
  уже есть).
- Сводка того, что применено, человеческим языком по группам шага ③ — вместо
  16 плашек. Сводка строится из **действующих** опций: зависимый флаг без
  humanize не показывается как включённый.
- Список дорожек карточками, без 7-колоночной таблицы:
  - имя, роль, короткий отчёт;
  - кнопки Baseline / Double / Enriched — только существующие;
  - по клику — piano-roll и плеер (текущий код `buildPreviewMarkup` и
    `wirePlayer` переносится как есть).
  - Перегенерация аппликатуры — в карточке дорожки, в разделе «Табы».
- **«Настройка DAW»** — чек-лист, зависящий от выбранных опций:
  - PITCH BEND RANGE = `hydra_pitch_bend_range`;
  - Picking Mode C7/C#7, если включён `pick_direction`;
  - Vel → Tightness, если включён `palm_mute_motion`.

  Это заменяет обе продублированные подсказки.
- **«Изменить звучание и пересобрать»** возвращает на ③ со значениями текущей
  версии. Каждая сборка — отдельная **версия** (v1, v2 …) с сохранёнными
  настройками и файлами, так что два варианта можно скачать и сравнить на слух.
  Это прямо отвечает решениям «решать на слух» от 2026-09-24.

## 4. Изменения в бэкенде (минимальные, аддитивные)

1. **Повторная обработка = новая версия.**
   - Снять 409 в `process_job`. Каждая обработка пишет в
     `uploads/<job>/renders/<n>/`, а её опции и отчёты ложатся в
     `job["renders"][n]`.
   - Разбор (`detected_tracks`) остаётся общим.
   - Миграция при чтении: старая работа без `renders` читается как одна версия
     из текущих полей. Файлы старых сессий не двигаются.
   - Это единственное нетривиальное изменение. Файлы на диске меняют место, поэтому
     проверить `download_track`, `download_zip`, `preview_track` и
     `/reports/...`.
2. **Групповые опции разворачиваются в поля по дорожкам на клиенте**, до отправки
   формы. Сервер получает ровно тот же набор `track_N_<effect>`, что и сейчас.
   Роль берётся из `detected_tracks`: на клиенте никакой новой музыкальной
   логики.
3. **Действующие опции в манифесте.** Зависимые флаги сохраняются как
   включённые, только если включён humanize той же дорожки. Сейчас это
   гарантирует только JS.
4. **Кнопка ZIP**, отдельный `_ALL.mid` на каждую версию.
5. Шаг в URL (`?step=`). Страница остаётся одним шаблоном с частичными
   include-файлами на каждый шаг, отдельные SPA-маршруты не нужны.

## 5. Приёмка

- **Эталонный тест формы.** Одна и та же отправка формы в старом и новом UI →
  одинаковые хэши всех MIDI. Минимум: Spring Melody (GP8, соло с авторскими
  сдвигами) и pnd.gp5. Три набора опций: только дефолты; всё оживление;
  «вместе с барабанами» + дубль + медиатор.
- **Путь «ничего не трогать»** (файл → далее → далее → обработать) даёт
  текущие дефолты.
- **Повторная обработка:** v2 с другими опциями не затирает файлы v1; обе
  версии скачиваются; старая сессия без `renders` открывается и скачивается.
- **Тесты.** Обновить 10 файлов, которые проверяют разметку и маршруты:
  - `test_track_processing_ui.py`, `test_hidden_32nds.py`,
    `test_gp_played_offsets.py`, `test_performance_life.py`;
  - `test_playable_tabs.py`, `test_arrangement_web.py`,
    `test_arrangement_openai_web.py`, `test_midi_patch_export.py`;
  - `test_projects_ui.py`, `test_sheetsage2_web.py`.

  Добавить тесты на версии, миграцию манифеста, действующие опции и
  разворачивание групповых опций.
- **Вёрстка:**
  - 1440 px — без горизонтальной прокрутки;
  - 375 px — без горизонтальной прокрутки, текущий шаг на первом экране;
  - клавиатурная навигация по степперу.
- **Проверка в браузере на реальном файле** (AGENTS.md, правила 4–5):
  загрузка → разбор → сводка → скачивание дорожки и `_ALL.mid`.

## 6. Как делать: два пути

**A. Сначала прототип в Claude Design (рекомендую).** Спорная часть — компоновка
шагов ② и ③ и матрица «по дорожкам». Её дешевле довести кликабельным макетом, чем
кодом с тестами.
- Что дать дизайнеру:
  - этот план;
  - снимок текущего экрана;
  - реальные данные Spring Melody: 9 дорожек, роли, доступные опции из
    `TRACK_EFFECTS`.
- Готовый бриф для Claude Design: [`docs/CLAUDE_DESIGN_PROMPT.md`](CLAUDE_DESIGN_PROMPT.md).
- Одобренный макет становится входом для сессии реализации.
- Первая версия прототипа (2026-09-26, кликабельная, все пять шагов, версии
  A/B): https://claude.ai/artifact/78AHmhHf8T7e8kqx3c7Mnp. Он приватный, его
  может открыть только владелец аккаунта; сессия реализации читает его через
  `Artifact read`.

**B. Сразу код.** Без макета. Этапы те же, но итераций по компоновке
будет больше, и каждая меняет шаблон и тесты.

## 8. Риски

- **Сдвиг путей файлов** при переходе на версии ломает скачивание старых
  сессий. Лечится миграцией при чтении и тестом на старый манифест.
- **Поток expression (Hermes/OpenAI)** со стадией `awaiting_hermes_draft`
  привязан к одной обработке. Нужно решить, к какой версии относится план
  (предложение: к той, из которой он собран; «применить» создаёт enriched внутри
  той же версии).
- **Групповые опции могут незаметно изменить набор полей.** Защита — эталонный
  тест формы, он пишется первым.
- **Роль «соло» определяется по имени дорожки** (`SOLO_TRACK_KEYWORDS`). При
  нестандартном имени пользователь должен иметь возможность сменить роль на ②.
  Это меняет только группу в UI; поля формы по-прежнему идут по дорожкам.

2. Названия групп и шагов — годятся ли «Звучание», «Ритм-секция», «Соло»,
   «Точность нот»?
3. План выразительности через OpenAI: оставить в ④ или спрятать под
   «Эксперименты»?
4. Путь A (Claude Design) или B (сразу код).
